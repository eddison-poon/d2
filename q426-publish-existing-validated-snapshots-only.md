## Objective
**Publish the already-refreshed, validated Q426 snapshots only.** Do not collect data again.

## Tasks
1. Work only inside `agenthub-testing-dashboard-fresh` on the intended `main` branch.
2. Inspect `git status`, `git diff`, and existing Q426 snapshot/validation evidence. Identify exactly which Q426 snapshot files were generated by the successful run; verify they remain present and unchanged.
3. Recheck the intended `origin` remote, branch, connectivity, and current `origin/main` state. Determine the exact reason for the earlier check failure; do not assume it was merely a network outage.
4. Verify the local branch is safe to publish relative to the current remote branch. If the remote advanced or diverged, **stop and report** rather than automatically rebasing, merging, resetting, or force pushing.
5. Reuse existing validation evidence where reliable; if necessary run **local, read-only validation only**, without Jira access or regenerating snapshots.
6. Only after all required safety checks pass, stage **only the validated Q426 snapshot files**. Review the staged diff to confirm no other files are included.
7. Commit with message: `Refresh Q426 dashboard snapshots`.
8. Push to `origin/main` using a normal push. Report the commit SHA, push result, and final `git status`.

## Strict constraints
- **Do not rerun Q426 refresh, Jira JQL queries, collectors, or any network data collection other than necessary Git checks/push.**
- Do not modify, stage, or publish Healthcheck or Regression snapshots or files.
- Do not stage `query-config.local.md`, credentials, private configuration, unrelated changes, or `__pycache__`.
- Do not use `git add .`, `git commit -a`, `git push --force`, or bypass existing Git/Auto-Publish safeguards.
- Do not overwrite or discard the validated local snapshots.
- If the existing snapshots cannot be tied reliably to the successful validation, or Git checks fail, **stop without committing or pushing**, preserve local files, and report the exact issue and next safe action.

## Deliverables
- Snapshot files identified and validation evidence
- Remote/branch verification results and diagnosis of any failure
- Exact files staged and committed
- Commit SHA, push status, and final Git status (if successful)
- Clear blocked-state explanation (if unsuccessful)
