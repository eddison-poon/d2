# Operations Manager — Phase C5.1: Jira Story Template and Sprint Planning Draft Workflow

## Objective
Introduce a reusable Markdown-based Jira Story Description Template and enable the existing Copilot Operations Manager to generate Jira Story drafts from Sprint Planning notes. Jira is strictly read-only in this phase. Maintain the existing lightweight, Markdown-first architecture.

## A. Repository review
Review existing Operations Manager agent instructions, README, Jira launcher and company Jira Assistant capabilities. Reuse existing functions. Do not introduce frameworks, dependencies, Python scripts or unnecessary architecture changes.

## B. Jira Story Description Template
Create `templates/jira-story-description.md` in the **copilot-operations-manager** repo, with this content:

```markdown
## Background
Briefly describe why this Story is required.

## Objective
Describe the expected business outcome.

## Scope
- Item 1
- Item 2

## Acceptance Criteria
- AC1: Expected behavior
- AC2: Expected behavior

## Additional Notes
Dependencies, assumptions, or references.
```

Requirements:
1. Preserve all five sections in order.
2. Replace instructional placeholders with information grounded in planning notes.
3. Use `TBD` when information is missing; never invent business requirements or acceptance criteria.
4. Always read the current template file when generating a Story draft, so future template edits take effect without Python changes.
5. Keep the template independently editable.

## C. Sprint Planning Draft Workflow
Make the smallest necessary change to existing Operations Manager agent instructions to support:
**Sprint Planning Notes → Jira Story Drafts**
1. Accept notes through Copilot chat or an existing Markdown file.
2. Identify proposed Stories and extract summaries and available metadata.
3. Generate each Description using the current template.
4. Identify missing required information.
5. Use existing approved Jira launcher Search to check for potential duplicates; never use Jira MCP.
6. Display a complete creation preview and stop for explicit approval. Do not create tickets in C5.1.

## D. Preview for each Story
Display Project, Issue Type, Summary, complete Description, Assignee, Sprint, Epic, Priority, Labels, duplicate-search result, missing information, and creation readiness. Distinguish supported/writable fields from unsupported or unverified fields. Do not silently omit requested metadata. Sprint/Epic may be omitted and added during later manual review.

## E. Read-only validation
Use synthetic Sprint Planning notes with two proposed Stories. Verify both are identified, the template is loaded, all five Description sections are populated, missing data becomes TBD, duplicate searches are scoped, unsupported fields are identified, and full previews are shown. If Jira Search cannot be safely performed, report it as BLOCKED rather than inventing results. No Jira writes.

## F. Boundaries
- No Jira create/update/delete/transition/comments.
- No changes to company Jira Assistant scripts, proxy, authentication, TLS or routing.
- No new dependencies or unnecessary code.
- Preserve unrelated repository changes.
- Do not commit or push Operations Manager changes automatically.

## G. Final report
Report files created/modified, template content, example Story drafts, duplicate-check evidence, field support/limitations, validation results, Git working-tree status, and readiness for C5.2. Stop before Jira creation.
