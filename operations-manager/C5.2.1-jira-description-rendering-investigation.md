# Operations Manager — C5.2.1: Jira Description Rendering Investigation (Read-only)

## Objective
Investigate why the newly created Jira Story's Description renders incorrectly in the Jira UI, despite a successful exact-text read-back. Identify a minimal, evidence-based way to produce correctly formatted Jira descriptions **before** C5.3 batch creation.

## Observed case
- Newly created Story: **ETIVAI-20691 — Health check script running on Jenkins**.
- C5.2 create and read-back both PASS; the stored UTF-8 Description matched the approved five-section Markdown text exactly.
- In the Jira UI, Markdown headings such as `## Background`, `## Objective`, and `## Scope` appear as awkward numbered/list-like headings (for example `1. Background`) instead of clean section headings.
- User confirms a **previous Agent Hub agent successfully produced correctly formatted Jira Descriptions**. Treat that working implementation/output as a primary comparison target, not as proof of any particular markup type.
- Desired visual structure: clear Background, Objective, Scope, Acceptance Criteria, Additional Notes headings; normal bullets for Scope and acceptance criteria; no unwanted numbering.
- The reusable source template `templates/jira-story-description.md` should remain easy to edit.
